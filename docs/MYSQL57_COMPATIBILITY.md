# MySQL 5.7.44 Compatibility

The production server uses MySQL 5.7.44. Dumps exported from MySQL 8 can fail during import because MySQL 5.7 does not support the `utf8mb4_0900_ai_ci` collation.

## Required Dump Conversion

Before importing a dump generated by MySQL 8, replace every `utf8mb4_0900_ai_ci` with `utf8mb4_unicode_ci`.

PowerShell:

```powershell
(Get-Content .\photography_system.sql -Raw) `
  -replace 'utf8mb4_0900_ai_ci', 'utf8mb4_unicode_ci' |
  Set-Content .\photography_system.mysql57.sql -Encoding UTF8
```

Linux:

```bash
sed 's/utf8mb4_0900_ai_ci/utf8mb4_unicode_ci/g' photography_system.sql > photography_system.mysql57.sql
```

Then import:

```bash
mysql -u photography_system -p photography_system < photography_system.mysql57.sql
```

## Database Charset

Create the database with a MySQL 5.7 compatible collation:

```sql
CREATE DATABASE IF NOT EXISTS photography_system
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

If the database already exists:

```sql
ALTER DATABASE photography_system
  DEFAULT CHARACTER SET utf8mb4
  DEFAULT COLLATE utf8mb4_unicode_ci;
```

## Notes

- `datetime(6)` is supported by MySQL 5.7.44.
- `bit(1)`, `tinyint(1)`, `enum`, `ROW_FORMAT = DYNAMIC`, stored procedures, and the views in the current dump are compatible with MySQL 5.7.44.
- The application should use Hibernate `org.hibernate.dialect.MySQLDialect`, not `MySQL8Dialect`, when connecting to MySQL 5.7.
